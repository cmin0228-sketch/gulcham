# 글침 (GEULCHIM) — 선택형 AI 문장 퇴고 에디터

> **“AI는 제안하고, 수정은 내가 결정한다.”**  
> 사용자가 문장별로 AI의 개입 범위를 선택하고, 제안을 참고해 원문을 직접 수정하는 선택형 문장 퇴고 웹앱

---

## 1. 프로젝트 개요

글침(GEULCHIM)은 일반적인 채팅형 AI가 글 전체를 임의로 다시 작성하면서 작성자 고유의 문체나 의도가 훼손되는 문제를 해결하기 위해 제작된 **문장 단위 선택형 퇴고 웹앱**입니다.

- **원고 입력 → 분석하기 → 문장별 카드 분리**의 직관적인 작업 흐름
- 각 문장마다 독립적인 3가지 개입 모드: **💬 진단만**, **✨ AI 고쳐쓰기**, **🔒 고정**
- AI 제안을 강제하지 않고 **사용자가 상단 입력창에서 직접 타이핑해 수정**
- **오래된 제안 방지(Stale Detection)**: 문장 수정 후 이전 AI 제안으로 덮어쓰이지 않도록 프로그램 수준에서 방어
- 오른쪽 사이드바에서 **실시간 완성 원고 자동 조립 및 통계 확인**
- 최초 원문과 현재 수정본의 **단어/토큰 단위 정밀 비교(Diff Modal)**
- **API 키 없이도 모든 흐름이 완전히 동작하는 오프라인 Mock 데모 모드 내장**
- 비밀 키를 클라이언트나 Git에 노출하지 않는 **독립 서버(Express) AI 프록시 구조**

## 2. 3가지 개입 모드 정책

| 모드 | 화면 명칭 | AI가 수행하는 작업 | 사용자 행동 | AI 문장 자동 적용 |
|---|---|---|---|---|
| `advice` | **💬 진단만** | 어휘 반복, 부사 남용, 경직된 표현 등 **문제점·개선 이유만 설명** (완성된 대체 문장 미생성) | 설명을 참고하여 **상단 입력창에서 직접 수정** | 불가 (적용 버튼 없음) |
| `rewrite` | **✨ AI 고쳐쓰기** | 원문의 문체를 존중한 **대체 문장 + 수정 이유 제안** | 제안을 검토한 후 **‘이 문장에 적용’**을 누르거나 직접 수정 | **사용자가 버튼을 클릭해야만 반영** (자동 덮어쓰기 없음) |
| `lock` | **🔒 고정** | AI 분석 및 제안 생성을 차단하며 제안 적용도 방어 | **사용자의 직접 타이핑 수정은 100% 허용** | **항상 불가** |

> 🛡 **안전장치(F06):** AI 제안이 생성된 이후 사용자가 문장을 직접 수정하면, 해당 제안은 즉시 `stale(오래된 제안)` 상태가 되어 적용이 비활성화되며, 수정한 원문 기준으로 다시 제안받을 수 있도록 안내합니다.

## 3. 기술 스택 및 구조

- **Frontend:** React 19, TypeScript, Vite, Tailwind CSS, Lucide React
- **Test:** Vitest, React Testing Library, JSDOM
- **Backend:** Node.js (ESM), Express, dotenv, cors
- **State & Domain:** 순수 TypeScript 도메인 분리 (`sentenceSplitter`, `draftAssembler`, `suggestionVersioning`, `diff`)
- **Persistence:** LocalStorage 자동 동기화 (`geulchim_document_state_v1`)

## 4. 실행 방법

### 4.1 개발 서버 실행 (프론트엔드)

API 키 없이 오프라인 데모 모드로 바로 실행할 수 있습니다:

```bash
npm run dev
```

브라우저에서 `http://localhost:5173`으로 접속합니다.

### 4.2 실제 AI 모델 연결 (선택 사항)

실제 생성형 AI(Google Gemini 또는 OpenAI)를 연동하려면 서버 환경 변수를 설정합니다:

1. 프로젝트 루트에 `.env` 파일을 생성합니다:
   ```bash
   cp .env.example .env
   ```
2. `.env` 파일에 API 키를 입력합니다 (둘 중 하나만 있어도 작동):
   ```env
   PORT=3001
   GEMINI_API_KEY=your_gemini_api_key_here
   # 또는
   OPENAI_API_KEY=your_openai_api_key_here
   ```
3. 백엔드 서버를 실행합니다:
   ```bash
   npm run server
   ```
4. 별도 터미널에서 프론트엔드를 실행합니다:
   ```bash
   npm run dev
   ```
   *상단 헤더에 `● 실제 AI 연동 모드` 녹색 배지가 표시됩니다.*

### 4.3 빌드 및 검사

```bash
# TypeScript 타입 검사 및 Vite 프로덕션 빌드
npm run build

# 빌드 결과 미리보기
npm run preview
```

### 4.4 자동 테스트 실행

수용 기준(T01~T14) 및 컴포넌트 동작을 검증하는 16개 테스트를 수행합니다:

```bash
npm test
```

## 5. 수용 기준 시나리오 검증 결과

`GLCHIM_ANTIGRAVITY_SPEC.md`에 명시된 14가지 필수 검증 시나리오 테스트 결과입니다:

| ID | 검증 항목 | 합격 여부 | 상세 동작 검증 내용 |
|---|---|:---:|---|
| **T01** | 첫 화면에 5문장 입력 → 분석하기 | **PASS** | 문맥과 구두점, 인용 부호를 고려해 정확히 5개의 문장 카드로 분리 |
| **T02** | 카드 2번 직접 타이핑 | **PASS** | 카드 내용과 우측 `완성 중인 원고` 미리보기가 포커스 손실 없이 실시간 갱신 |
| **T03** | `진단만` 모드 선택 | **PASS** | 문제점 목록(`issues[]`)과 조언만 표시되며 대체 문장 및 적용 버튼은 비노출 |
| **T04** | `AI 고쳐쓰기` 선택 → 제안 생성 | **PASS** | 대체 문장 및 수정 이유가 표시되며 적용 전까지 원문 카드는 불변 유지 |
| **T05** | 2번 카드의 제안만 적용 | **PASS** | 2번 카드만 대체 문장으로 교체되고 다른 모든 카드는 상태 불변 |
| **T06** | 3번 카드를 `고정`으로 변경 | **PASS** | AI 제안 생성 및 적용이 프로그램 수준에서 차단되며, 직접 타이핑은 자유롭게 허용 |
| **T07** | 제안 생성 후 원문 직접 수정 | **PASS** | 이전 제안이 즉시 `stale` 처리되고 덮어쓰기 적용 버튼이 비활성화됨 |
| **T08** | 카드 1개 `원문 복원` | **PASS** | 해당 카드만 최초 분석 당시 텍스트로 복원되며 다른 카드의 수정은 유지 |
| **T09** | 수정 전후 비교 (Diff) | **PASS** | 최초 입력 원문과 현재 조립 원고 간의 단어 단위 삭제(취소선)·추가(하이라이트) 비교 모달 제공 |
| **T10** | 새로고침 (Persistence) | **PASS** | 브라우저 LocalStorage에 임시 저장되어 새로고침 후에도 작업 상태 복원 |
| **T11** | 최종본 복사 및 TXT 저장 | **PASS** | 화면에 보이는 현재 원고와 100% 동일한 UTF-8 문자열을 클립보드 복사 및 다운로드 |
| **T12** | 외부 AI 요청 실패 | **PASS** | 네트워크 에러 시 오류 배너 표시 후 안전하게 Mock 규칙으로 대체하여 편집 내용 보존 |
| **T13** | 타이핑 도중 문장부호 입력 | **PASS** | 마침표, 따옴표 입력 시 커서가 튀거나 카드가 임의로 재분할되지 않음 |
| **T14** | 문장 사이 문단 구분 보존 | **PASS** | 문단 구분이 있는 원고를 분리한 후 최종 조립 시 `\n\n` 구조가 온전히 보존됨 |

## 6. 디자인 개선 사항

기존 데모의 답답하거나 산만한 요소를 걷어내고 **‘조용한 서재, 신뢰할 수 있는 에디토리얼 도구’**를 테마로 새롭게 디자인했습니다.

1. **시각적 위계 확립:** 미색 바탕(`bg-[#f7f9f6]`), 백색의 정돈된 카드 패널, 차콜 딥그린(`text-ink-900`, `bg-sage-primary`) 포인트 컬러 적용.
2. **모드별 명확한 인지성:** 💬 진단만(따뜻한 앰버), ✨ AI 고쳐쓰기(부드러운 라벤더), 🔒 고정(차분한 로즈)을 테두리와 배지 색상으로 구분하여 혼동을 원천 방지.
3. **타이포그래피 및 가독성:** Pretendard 기반 한국어 행간(leading-relaxed)과 15~16px 폰트로 장문 입력 시 피로도 대폭 완화.
4. **반응형 2열 레이아웃:** 데스크톱에서는 2/3 문장 카드 목록 + 1/3 Sticky 완성본 미리보기로 스크롤 중에도 원고의 전체 호흡을 한눈에 점검 가능.
