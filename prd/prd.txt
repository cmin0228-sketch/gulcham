**버전:** 1.0  
**작성일:** 2026.11.09  
**제품 유형:** AI 기반 웹 텍스트 에디터

**프로젝트명:** 글침 — AI 수정 범위 통제형 자기 퇴고 에디터

# 1. 제품 개요

## 1.1 서비스 소개

글침은 사용자가 작성한 글을 직접 수정하면서 생성형 AI의 분석과 윤문 제안을 선택적으로 활용할 수 있는 웹 기반 텍스트 에디터이다.

일반적인 AI 윤문 서비스에서는 사용자가 수정 방향을 요청하면 AI가 새로운 문장을 생성한다. 이후 사용자는 수정된 결과를 수용하거나 원문과 비교하여 다시 편집해야 한다.

글침은 이 과정에서 사용자가 원문의 수정 권한을 직접 설정하고, AI의 제안을 참고하면서 글을 편집할 수 있도록 한다.

사용자는 AI가 검토할 문장과 보존할 문장을 지정할 수 있으며, AI가 제안한 문장을 그대로 적용하거나 일부를 수정하거나 완전히 무시할 수 있다.

**글침의 핵심은 AI가 문장을 대신 완성하는 것이 아니라, 사용자가 AI의 도움을 받으면서 자신의 글을 직접 완성하는 것이다.**

## 1.2 핵심 가치

**AI는 제안하고, 수정은 내가 결정한다.**

글침은 다음 세 가지 가치를 제공한다.

1. **수정 권한 통제:** 사용자가 AI의 개입 범위를 지정한다.
2. **자기 주도적 퇴고:** AI 제안을 참고하면서 원문을 자유롭게 수정한다.
3. **원문 보존:** AI가 사용자가 지정한 영역을 임의로 변경하지 못하도록 프로그램 차원에서 제어한다.

## 1.3 제품 비전

사용자가 자신의 글에 대한 통제권을 유지하면서 AI의 분석 능력을 활용할 수 있는 글쓰기 환경을 제공한다.

장기적으로는 사용자가 AI의 어떤 제안을 받아들이고 어떤 표현을 유지하는지 기록하여 개인의 퇴고 성향을 파악하는 서비스로 발전시키고자 한다.

# 2. 문제 정의

## 2.1 문제 배경

생성형 AI는 문법 수정, 문장 다듬기, 표현 개선, 어휘 추천 등 다양한 글쓰기 보조 기능을 제공한다.

그러나 사용자가 AI의 수정 결과 전체를 원하는 것은 아니다.

예를 들어 글을 작성할 때 다음과 같은 상황이 발생할 수 있다.

- 특정 문장은 원래의 표현을 유지하고 싶다.
- 일부 문장만 자연스럽게 다듬고 싶다.
- AI가 제안한 표현을 참고하되 직접 다시 작성하고 싶다.
- AI의 수정 결과에서 마음에 드는 부분만 선택하고 싶다.
- 수정 전후의 차이를 확인하면서 글을 완성하고 싶다.

이러한 작업은 기존 생성형 AI에서도 프롬프트와 반복적인 대화를 통해 수행할 수 있다.

하지만 여러 문장에 서로 다른 조건을 적용하고, 수정 내용을 비교하여 부분적으로 반영하는 과정은 별도의 편집 인터페이스를 통해 더 편리하게 제공할 가능성이 있다.

글침은 이러한 가능성에 주목한다.

## 2.2 핵심 문제

> 사용자는 생성형 AI의 문장 개선 능력을 활용하고 싶지만, 원문의 어떤 부분을 수정하고 보존할 것인지 직접 통제하면서 글을 편집할 수 있는 환경이 필요하다.

## 2.3 해결 방향

기존의 'AI에게 전체 글의 수정을 요청하는 방식'에서 벗어나 다음 과정을 하나의 화면에서 수행할 수 있도록 한다.

**원문 작성 → 수정 범위 지정 → AI 제안 생성 → 원문 직접 수정 → 부분 적용 → 최종본 완성**

# 3. 목표 사용자

## 3.1 핵심 타깃

**블로그, SNS, 에세이 등 자신의 글을 작성하고 직접 퇴고하는 사용자**

특히 AI의 도움을 활용하고 싶지만, 원래의 문체와 표현을 유지하는 것을 중요하게 생각하는 사용자를 대상으로 한다.

## 3.2 대표 페르소나

**홍윤정 (22세, 대학생)**

- 개인 블로그를 운영한다.
- 글을 작성한 후 자연스럽지 않은 문장을 수정하는 편이다.
- 비슷한 표현을 반복해서 사용한다는 점을 인식하고 있다.
- AI의 윤문 결과를 참고하지만 자신의 말투는 유지하고 싶어 한다.

**사용자 목표**

"AI가 글을 다 바꿔주는 것보다, 고칠 만한 부분을 알려주면 내가 직접 수정하고 싶어요."

※ 페르소나와 사용자 목표는 기획을 위한 가정이며, 실제 사용자 조사에서 추가 검증이 필요하다.

# 4. 제품 목표 및 성공 기준

## 4.1 제품 목표

### 목표 1. AI 수정 범위 통제

사용자가 특정 문장에 대한 AI의 개입 여부를 설정할 수 있도록 한다.

### 목표 2. 원문 직접 편집

AI 제안을 확인하는 동시에 원문을 자유롭게 수정할 수 있도록 한다.

### 목표 3. 선택적 수정 반영

AI의 수정 결과가 전체 문서를 자동으로 덮어쓰지 않도록 한다.

### 목표 4. 원문 보존

AI의 수정 대상에서 제외한 영역은 AI 제안 적용 과정에서도 원문이 유지되도록 한다.

## 4.2 MVP 성공 기준

다음 조건을 만족하면 핵심 기능이 구현된 것으로 판단한다.

| 평가 항목 | 성공 기준 |
|---|---|
| 원문 편집 | 사용자가 편집창에서 글 전체를 직접 수정할 수 있음 |
| 수정 범위 지정 | 문장별 AI 수정 권한을 설정할 수 있음 |
| AI 제안 | 수정이 허용된 문장에 대해 수정안을 받을 수 있음 |
| 부분 적용 | AI 제안을 문장별로 선택하여 적용할 수 있음 |
| 잠금 보존 | AI 제안 적용 시 잠긴 문장이 변경되지 않음 |
| 수동 편집 | 잠긴 문장도 작성자 본인은 수정할 수 있음 |
| 수정 결과 | 사용자가 직접 수정한 내용이 최종본에 반영됨 |
| 최종 저장 | 완성한 원고를 복사하거나 TXT로 저장할 수 있음 |

이후 사용자 테스트를 통해 기존 채팅형 AI 윤문 방식과 작업 시간, 조작 횟수, 원하지 않는 변경 발생 여부 등을 비교한다.

# 5. 핵심 기능 요구사항

## FR-01. 원문 직접 편집

**우선순위: P0 — 필수**

### 기능 설명

사용자는 메인 에디터에서 글 전체를 직접 입력하고 수정할 수 있다.

에디터는 일반적인 문서 편집기처럼 작동해야 한다.

AI의 수정안이 생성된 이후에도 사용자는 원문을 자유롭게 편집할 수 있다.

### 세부 요구사항

- 사용자는 텍스트를 입력하거나 붙여넣을 수 있다.
- 사용자는 문장을 추가, 삭제, 수정할 수 있다.
- 수정한 내용은 즉시 현재 작업 원고에 반영된다.
- AI 제안을 적용하지 않아도 글을 완성할 수 있다.
- 사용자는 실행 취소 및 다시 실행 기능을 사용할 수 있다.
- AI가 제안한 문장을 적용해도 이후 다시 직접 수정할 수 있다.

### 중요 정책

**원문 잠금은 사용자의 편집을 제한하지 않는다.**

잠금은 AI의 수정 권한을 제한하는 기능이다.

따라서 사용자는 잠긴 문장도 직접 수정할 수 있어야 한다.

---

## FR-02. AI 수정 권한 설정

**우선순위: P0 — 필수**

### 기능 설명

사용자는 문장 단위로 AI의 개입 수준을 지정할 수 있다.

### 권한 유형

| 권한 | AI 동작 | 사용자 동작 |
|---|---|---|
| 수정 제안 허용 | 문제 분석 및 수정안 생성 | 자유롭게 수정하거나 제안 적용 |
| 분석만 허용 | 문제점과 개선 방향 설명, 대체 문장 생성 없음 | 설명을 참고하여 직접 수정 |
| AI 제외(잠금) | 해당 문장에 대한 분석·수정 제안 생성 안 함 | 직접 수정 가능 |

### 세부 요구사항

- 기본 권한은 '수정 제안 허용'으로 설정한다.
- 사용자는 문장을 선택하여 권한을 변경할 수 있다.
- 권한별 상태를 색상 또는 아이콘으로 구분한다.
- 여러 문장을 선택하여 권한을 일괄 변경할 수 있도록 확장할 수 있다.
- AI 제외 영역에는 AI 수정안을 적용할 수 없다.
- 사용자가 직접 수정할 경우에는 권한과 관계없이 변경할 수 있다.

### 예외 처리

사용자가 문장을 수정하여 문장 경계가 달라지면 기존 권한이 다른 문장에 잘못 적용되지 않아야 한다.

문장 분리 결과가 변경되는 경우에는 권한을 재확인하도록 안내할 수 있다.

---

## FR-03. AI 수정 방향 설정

**우선순위: P0 — 필수**

### 기능 설명

AI 제안을 생성하기 전에 수정 목적과 수정 강도를 선택할 수 있다.

### 수정 목적

1. **간결하게:** 불필요한 표현을 줄인다.
2. **자연스럽게:** 어색한 문장 흐름을 개선한다.
3. **쉽게:** 어려운 표현을 이해하기 쉬운 표현으로 바꾼다.
4. **반복 줄이기:** 반복되는 표현을 검토한다.

### 수정 강도

| 수준 | 설명 |
|---|---|
| 최소 수정 | 원문의 표현과 구조를 최대한 유지 |
| 보통 수정 | 의미를 유지하면서 문장 표현 개선 |
| 적극 수정 | 문장 구조 변경을 포함한 폭넓은 수정 제안 |

### 세부 요구사항

- 사용자는 수정 목적을 선택할 수 있다.
- 수정 강도는 기본적으로 '최소 수정'을 사용한다.
- 수정 목적과 강도는 AI 요청에 포함된다.
- AI가 생성한 수정안은 사용자 승인 전까지 원문을 변경하지 않는다.

---

## FR-04. AI 수정 제안

**우선순위: P0 — 필수**

### 기능 설명

사용자가 AI 분석을 요청하면, 설정된 권한에 따라 문장별 분석 결과를 생성한다.

### 수정 제안 허용 상태

AI는 다음 정보를 제공한다.

- 원문
- 수정 제안 문장
- 수정 이유

**예시**

원문:
"오늘은 진짜 너무 정말 기분이 좋았다."

AI 제안:
"오늘은 정말 기분이 좋았다."

수정 이유:
"비슷한 강조 표현이 연속으로 사용되어 일부를 줄였습니다."

### 분석만 허용 상태

AI는 수정 문장을 생성하지 않고 문제점과 검토 방향만 설명한다.

예시:

"강조 표현이 여러 번 등장합니다. 강조할 표현을 하나 선택하거나 구체적인 묘사로 대체할 수 있습니다."

### AI 제외 상태

해당 문장은 AI 제안 목록에 포함되지 않는다.

### 세부 요구사항

- AI 제안은 원문과 구분된 영역에 표시한다.
- 수정 이유를 함께 제공한다.
- 하나의 문장에 대한 AI 제안은 다른 문장에 자동으로 적용되지 않는다.
- 사용자가 수정안을 거절하거나 무시할 수 있다.
- 제안 생성 중에는 진행 상태를 표시한다.
- API 오류가 발생하더라도 원문은 유지한다.

---

## FR-05. AI 제안과 원문 동시 편집

**우선순위: P0 — 필수**

### 기능 설명

원문과 AI 제안을 동시에 확인하면서 원문을 편집할 수 있도록 한다.

### 화면 구성

**왼쪽: 원문 편집 영역**

사용자가 직접 입력하는 공간이다.

**오른쪽: AI 제안 영역**

현재 선택한 문장에 대한 AI의 분석과 수정안을 보여준다.

### 세부 요구사항

- 원문 편집창은 항상 편집할 수 있어야 한다.
- AI 제안을 확인하는 동안에도 타이핑할 수 있어야 한다.
- 사용자가 문장을 선택하면 관련 제안을 보여준다.
- AI 제안을 누르면 해당 문장으로 이동할 수 있다.
- 사용자는 AI 제안을 적용하지 않고 직접 수정할 수 있다.
- AI 제안을 적용한 이후에도 수정한 내용을 다시 편집할 수 있다.

### 핵심 UX 원칙

**AI 제안은 편집을 돕는 참고 자료이며, 원문을 대체하는 최종 결과물이 아니다.**

---

## FR-06. 수정안 부분 적용

**우선순위: P0 — 필수**

### 기능 설명

사용자는 AI 제안 중 원하는 문장만 선택하여 적용할 수 있다.

### 세부 요구사항

- 각 제안에 '적용' 버튼을 제공한다.
- 적용 시 해당 문장만 수정한다.
- 다른 문장은 변경하지 않는다.
- AI 제외 상태의 문장은 적용 대상이 될 수 없다.
- 적용한 변경은 실행 취소할 수 있다.
- 사용자가 직접 수정한 문장에 오래된 AI 제안이 적용되어 내용을 덮어쓰지 않도록 한다.

### 중요 예외 처리

AI 제안이 생성된 이후 사용자가 원문을 직접 수정했다면, 기존 제안의 기준 문장과 현재 문장이 달라질 수 있다.

이 경우 기존 제안을 무조건 덮어쓰지 않는다.

다음과 같이 안내한다.

"제안 생성 이후 원문이 변경되었습니다. 현재 문장에 맞춰 수정안을 다시 생성하시겠습니까?"

이 기능은 사용자의 수동 편집 내용을 보호하기 위해 반드시 필요하다.

---

## FR-07. 원문 잠금 및 보존

**우선순위: P0 — 필수**

### 기능 설명

사용자가 AI 제외 상태로 지정한 문장은 AI가 임의로 수정할 수 없도록 한다.

### 구현 원칙

프롬프트에 '수정하지 마세요'라고 지시하는 것만으로 구현하지 않는다.

프로그램이 문장별 권한을 관리하고, AI의 수정안을 적용할 때 권한을 검증한다.

### 처리 과정

1. 사용자가 AI 제외 문장을 지정한다.
2. 프로그램이 해당 문장의 식별자와 권한을 저장한다.
3. AI 수정 요청에서는 해당 문장을 수정 대상에서 제외한다.
4. AI 응답을 받은 뒤 수정 권한을 다시 검사한다.
5. 사용자가 승인한 수정 제안만 해당 문장에 적용한다.
6. 잠긴 문장은 AI에 의해 변경되지 않는다.

### 개인정보 관련 고려사항

AI 제외 문장을 수정 대상으로 보내지 않는 것과 AI에게 내용을 전혀 전송하지 않는 것은 구분해야 한다.

MVP에서는 AI 제외 문장을 원칙적으로 외부 AI 요청에서 제외하고, 문맥 제공이 필요한 기능을 추가할 경우 전송 여부를 사용자에게 명확하게 안내한다.

# 6. 사용자 흐름

## 6.1 기본 사용 시나리오

### STEP 1. 글 입력

사용자가 메인 에디터에 작성 중인 글을 붙여넣는다.

### STEP 2. AI 수정 범위 지정

사용자는 AI의 도움을 받을 문장과 보존할 문장을 선택한다.

예시:

- 1번 문장: AI 제외
- 2번 문장: 수정 제안 허용
- 3번 문장: 분석만 허용

### STEP 3. 수정 방향 설정

사용자는 '자연스럽게', '최소 수정'을 선택한다.

### STEP 4. AI 제안 생성

프로그램이 각 문장의 권한을 확인한 후 AI에게 필요한 분석을 요청한다.

### STEP 5. 원문 직접 수정

사용자는 AI 제안을 확인하면서 원문 편집창에서 글을 직접 수정한다.

AI가 추천한 문장 중 마음에 드는 부분만 반영할 수도 있다.

### STEP 6. 결과 확인

사용자는 원본과 수정본을 비교한다.

### STEP 7. 최종 원고 완성

완성한 글을 복사하거나 파일로 저장한다.

## 7.1 메인 화면

오른쪽 사이드바:
- AI 수정 방향
- 수정 강도

- 문장별 수정 권한 설정

하단:
- 글자 수
- 어절 수
- AI 수정 허용 문장 수
- AI 제외 문장 수

## 7.2 AI 제안 화면

**화면 목적**

원문을 직접 수정하면서 AI 제안을 검토할 수 있도록 한다.

### 화면 구성

**왼쪽: 편집기**

- 현재 작업 원고
- 자유로운 텍스트 수정
- 문장별 권한 표시
- AI 제안이 있는 문장 표시

**오른쪽: AI 제안 패널**

- 선택한 원문
- AI 수정 제안
- 수정 이유
- 적용 버튼
- 다시 생성 버튼

### 화면 동작

사용자가 원문의 문장을 선택하면 오른쪽 패널이 해당 문장의 AI 제안으로 변경된다.

'적용' 버튼을 누르면 왼쪽 편집기에서 해당 문장만 교체된다.

사용자가 직접 타이핑하면 현재 작업 원고에 즉시 반영된다.

## 7.3 수정 비교 화면

**화면 목적**

사용자가 원본과 현재 원고의 차이를 확인할 수 있도록 한다.

### 화면 구성

- 왼쪽: 최초 입력한 원본
- 오른쪽: 현재 수정한 원고
- 변경 사항 강조
- 원본 복원
- 최종 원고 저장

# 8. 시스템 구조

## 8.1 권장 기술 스택

| 구분 | 기술 | 역할 |
|---|---|---|
| 프론트엔드 | React | 실시간 원문 편집 및 AI 제안 인터페이스 |
| 텍스트 에디터 | Tiptap | 편집 상태 및 문장 선택 관리 |
| 백엔드 | Python + FastAPI | AI 요청 및 문서 데이터 처리 |
| LLM | OpenAI API 등 | 문장 분석 및 수정안 생성 |
| 한국어 분석 | Kiwipiepy | 문장 분리 및 형태소 분석 |
| 데이터베이스 | SQLite | 문서 및 수정 이력 저장 |
| 스타일 | CSS | 화면 디자인 및 반응형 UI |

### 기술 선택 이유

기존에 계획한 Streamlit도 Python 기반의 프로토타입을 빠르게 구현할 수 있다는 장점이 있다.

다만 새로운 글침은 원문 편집, 문장 선택, 부분 교체, 실시간 변경 관리가 핵심이다.

따라서 실제 서비스 구현에서는 텍스트 에디터 제어에 유리한 React 기반 프론트엔드가 더 적합할 수 있다.

MVP의 초기 기능 검증은 기존 HTML 프로토타입으로 진행하고, 본격적인 개발에서는 React와 FastAPI 구조를 권장한다.

# 9. AI 처리 정책

## 9.1 기본 원칙

AI는 원문을 직접 수정하지 않는다.

AI는 수정 제안을 생성하며, 실제 편집 내용의 변경은 사용자의 입력이나 명시적인 적용 동작에 의해 발생한다.

## 9.2 프롬프트 설계

AI 요청에는 다음 정보를 포함한다.

- 수정 대상 문장
- 수정 목적
- 수정 강도
- 응답 형식

AI는 수정된 문장과 수정 이유를 구조화된 형태로 반환하도록 한다.

## 9.3 서버 측 검증

AI 응답을 받은 후 다음을 확인한다.

1. 요청한 문장에 대한 응답인지 확인한다.
2. 수정 권한이 존재하는지 확인한다.
3. 현재 원문 버전과 제안 생성 당시 버전이 같은지 확인한다.
4. 사용자가 적용을 승인했는지 확인한다.
5. 조건을 만족하는 경우에만 해당 문장을 교체한다.

**AI가 반환한 문서 전체를 현재 원고에 그대로 덮어쓰는 방식은 사용하지 않는다.**

# 10. 비기능 요구사항

## 10.1 성능

- 일반적인 텍스트 입력과 직접 편집은 지연 없이 작동하도록 한다.
- 1,000~3,000자 분량의 텍스트에서도 원문 편집이 원활해야 한다.
- AI 요청 중에도 원문 편집이 가능해야 한다.
- AI 응답 시간은 별도로 표시한다.

단, 외부 LLM의 응답 시간은 네트워크 상태와 모델에 따라 달라지므로 일정한 응답 시간을 보장하는 요구사항으로 설정하지 않는다.

## 10.2 안정성

- AI 요청 실패 시 원문을 보존한다.
- AI 응답 오류가 발생해도 직접 편집 기능은 정상 작동해야 한다.
- 사용자가 작성한 원고가 예기치 않게 사라지지 않도록 임시 저장 기능을 고려한다.
- 변경된 원문에 오래된 AI 수정안이 잘못 적용되지 않도록 한다.

## 10.3 개인정보 및 보안

- API 키는 서버에서 관리한다.
- 사용자에게 외부 AI 전송 여부를 안내한다.
- AI 제외 영역은 기본적으로 수정 대상 요청에서 제외한다.
- 문서 저장 여부 및 삭제 방법을 명확하게 제공한다.
- 외부 AI 제공업체의 데이터 처리 정책을 확인하고 안내한다.

특히 'AI 제외' 기능을 개인정보 보호 기능이라고 단정하지 않는다. AI의 수정 권한과 데이터 전송 권한은 서로 다른 개념으로 관리한다.

# 13. 테스트 시나리오

## TC-01. 원문 직접 수정

**조건:** 원문이 입력된 상태

**동작:** 사용자가 편집창에서 문장을 수정한다.

**기대 결과:** 수정 내용이 즉시 현재 원고에 반영된다.

## TC-02. AI 제외 문장 보호

**조건:** 1번 문장이 AI 제외 상태

**동작:** 전체 글에 대한 AI 수정을 요청한다.

**기대 결과:** 1번 문장은 AI 수정 대상에서 제외된다.

## TC-03. AI 제외 문장 수동 수정

**조건:** 1번 문장이 AI 제외 상태

**동작:** 사용자가 해당 문장을 직접 수정한다.

**기대 결과:** 직접 수정한 내용은 정상적으로 반영된다.

## TC-04. AI 수정안 부분 적용

**조건:** 2번 문장과 3번 문장에 수정 제안이 존재한다.

**동작:** 사용자가 2번 문장의 제안만 적용한다.

**기대 결과:** 2번 문장만 변경되고 3번 문장은 유지된다.

## TC-05. AI 제안 무시

**조건:** AI 수정안이 생성된 상태

**동작:** 사용자가 AI 제안을 적용하지 않고 원문을 직접 수정한다.

**기대 결과:** 사용자의 수정 내용만 최종 원고에 반영된다.

## TC-06. 오래된 제안 적용 방지

**조건:** AI 제안 생성 후 사용자가 해당 문장을 직접 수정했다.

**동작:** 사용자가 이전 AI 제안의 적용 버튼을 누른다.

**기대 결과:** 원문을 즉시 덮어쓰지 않고 재확인 또는 제안 재생성을 안내한다.

## TC-07. AI 요청 실패

**조건:** API 호출 중 오류 발생

**동작:** AI 제안 요청이 실패한다.

**기대 결과:** 원문은 보존되고 사용자는 계속 직접 편집할 수 있다.

# 14. 경쟁 서비스와의 차별화

글침은 생성형 AI가 제공하는 문장 분석 능력 자체를 경쟁력으로 주장하지 않는다.

일반적인 채팅형 AI에서도 문장 교정, 부분 수정, 문체 보존 요청이 가능하다.

따라서 글침은 **특정 글쓰기 작업을 반복적으로 수행하기 편리한 인터페이스와 편집 제어 기능**에 집중한다.

| 비교 항목 | 일반적인 채팅형 AI 사용 | 글침의 목표 |
|---|---|---|
| 수정 범위 지정 | 자연어 지시로 가능 | 문장 선택과 권한 설정 |
| 원문 직접 편집 | 제품의 편집 기능에 따라 다름 | 항상 편집 가능한 원문 중심 UI |
| 부분 수정 적용 | 지원 방식이 제품마다 다름 | 문장별 선택 적용 |
| AI 제외 영역 | 지시 또는 편집 기능으로 관리 | 프로그램의 권한 검증으로 관리 |
| 수정 결과 비교 | 제품에 따라 가능 | 원문과 현재 원고의 변경 사항 표시 |
| 퇴고 성향 기록 | 별도 정리 또는 기존 기능 활용 | 향후 구조화된 기록 제공 |

글침의 차별성은 다른 생성형 AI가 이러한 작업을 수행할 수 없다는 데 있지 않다.

**사용자가 원문을 직접 편집하는 과정에서 AI의 개입 범위를 일관된 방식으로 제어할 수 있도록 설계한다는 점에 있다.**

실제 효율성의 우위는 사용자 테스트를 통해 검증해야 한다.

# 15. 최종 제품 정의

## 서비스명

**글침 (GEULCHIM)**

## 서비스 유형

AI 수정 범위 통제형 자기 퇴고 에디터

## 핵심 기능

사용자가 문장별 AI 수정 권한을 설정하고, AI의 제안을 참고하면서 원문을 직접 수정하며, 필요한 수정안만 선택적으로 반영하는 기능

## 핵심 차별성

AI가 생성하는 최종 결과물보다 사용자가 AI의 개입과 수정 과정을 직접 통제하는 편집 경험을 중시한다.

## 핵심 메시지

**AI는 제안하고, 수정은 내가 결정한다.**

## 제품이 제공하는 경험

글침은 사용자가 AI의 수정안을 수락하거나 거절하는 데 그치지 않고, 수정안을 참고하여 자신이 원하는 표현을 직접 만들어 갈 수 있도록 돕는다.

궁극적으로 생성형 AI의 효율성과 작성자의 편집 자율성을 함께 확보하는 것을 목표로 한다.
